# Writing Tome mods in Rust

Two crates:

- **`tome-sys`**: raw bindings to `sdk/include/tome/tome.h`, generated by
  `tools/gen-rust-bindings.sh` and committed, so building a mod needs neither
  bindgen nor libclang. The header documents every function.
- **`tome`**: a safe layer: the lifecycle as plain functions, closures for
  callbacks, `Result`s, version checks, and panics turned into crashes Tome
  reports.

`examples/hello-rs` is the hello example in Rust: natives, a main menu
button, events, a hook, a chat command, settings, a keybind and a popup.
`../templates/rust` is the smallest mod to start from.

## Setup

```sh
rustup target add i686-pc-windows-gnu    # Warcraft III is a 32-bit process
# and MinGW's i686 cross compiler (Fedora: mingw32-gcc, Debian: gcc-mingw-w64-i686)
cargo build --release                     # in sdk/rust
```

`.cargo/config.toml` builds for `i686-pc-windows-gnu`, links with
`i686-w64-mingw32-gcc`, links MinGW's runtime statically (the game has no
`libgcc_s_dw2-1.dll`), and runs `cargo test` under Wine. A mod in its own
repository needs the same file.

Tome's own CMake build compiles the crates and `hello-rs` when cargo and the
target are installed (`TOME_BUILD_RUST`: `AUTO`, `ON`, `OFF`), runs the
`tome` crate's tests in `ctest`, and `tools/e2e-test.sh` runs `hello-rs` in
the game.

## A mod

`Cargo.toml`:

```toml
[package]
name = "my-mod"
edition = "2024"

[lib]
crate-type = ["cdylib"]   # my_mod.dll: tome.mod.json "entry"

[dependencies]
tome = { path = "../tome/sdk/rust/tome" }   # or a git dependency

[profile.release]
strip = true
```

`src/lib.rs`:

```rust
use tome::{Event, Integer, Tome};

tome::native! {
    /// native MyLog takes integer value returns nothing
    fn my_log(value: Integer) {
        tome::info!("MyLog({value})");
    }
}

fn load(tome: Tome) -> Result<(), String> {
    tome::info!("loaded in Tome {}", tome.version());
    Ok(())
}

fn enable(tome: Tome) {
    let _ = tome.register_native("MyLog", my_log);
    let _ = tome.on_event(Event::GAME_START, move |info| {
        let _ = tome.display_text(&format!("Welcome to {}", info.map_name()), 5.0);
    });
}

tome::export_mod! { load: load, enable: enable }
```

Then a `tome.mod.json` beside it as for any mod (`"entry": "my_mod.dll"`,
`"natives": ["native MyLog takes integer value returns nothing"]`), and
the DLL and `tome.mod.json` in a folder in `tome/mods/`. Inside Tome's
build, `tome_add_rust_mod()` and `tome_package()` (`sdk/TomeMod.cmake`) do
that and make a `.tome`; see `sdk/rust/CMakeLists.txt`. Elsewhere a `.tome`
is a zip of the folder with `tome.mod.json` at the top:
`cmake -E tar cf my-mod.tome --format=zip tome.mod.json my_mod.dll`.

## How it fits Tome

- **Panics** are caught at every call from Tome. The message and where it
  happened go to `tome.log`, and the mod raises `TOME_EXCEPTION_MOD_FAILED`,
  so Tome abandons the call and disables the mod as for a fault in C (a
  native returns 0). An unwind never crosses into the game, where Rust would
  abort the process. Threads a mod starts itself aren't guarded: a panic
  there ends only that thread.
- **`Tome`** is `Copy` but not `Send`. Tome calls mods on the main thread,
  so closures registered through it don't need `Send`. Capture `tome` in a
  closure to use it there, and keep state in `Cell`s, `RefCell`s or `Rc`s.
  Closures are `Fn`, because a callback can run again while it's still
  running (JASS calling back into a native).
- **Callbacks** are kept while Tome may call them: until the mod is
  disabled, until the same button (`on_click`) or key (`on_keybind`) is
  registered again, until a popup's has run, or not at all if Tome refused
  the registration. They're freed once none of the mod's code is running,
  so registering a button again from its own click is fine. Register them
  in `enable`.
- **Hooks** run on whatever thread calls the hooked function, so they're
  plain `fn(&mut HookCall)` with state in atomics. The logging macros
  (`tome::info!` and the rest) work on any thread.
- **Natives** come from `tome::native!`: `extern "C"` functions in the
  engine's ABI (`Real` is a pointer to the float, `RealRet` its bits,
  `JString`/`StringRet` the game's strings, `Code` a script function to run
  later). `register_native` only accepts JASS types.
- **Older Tome versions:** each method checks the API version and the
  table's size, and returns `Error::UNAVAILABLE` (or nothing) when the
  running Tome lacks the function. Event fields an older Tome doesn't fill
  read as empty, 0 or `None`.
- **Windows 10 or later:** Rust's standard library needs it on this target.

## Updating the bindings

After a change to `tome.h`, run `tools/gen-rust-bindings.sh` (bindgen:
`cargo install bindgen-cli`; it needs libclang and the MinGW headers) and
wrap the new functions in `tome`. The `tome_rust_bindings_current` test
fails while the committed file is out of date.
